# Backup UX and volatile PSBT exchange — 6 November 2026

Built on the accepted Backup and Restore runtime, without changing Core,
KeePassXC, kernel, Debian packages, firmware or installer disk policy.

## Navigation and concurrency

Settings, Backup and Restore, chain-copy progress, watch-only transfer and
configuration transfer are independent non-modal windows. The Home registry
keeps jobs alive even when a menu closes, and opening a task again raises the
same instance. Back while busy minimizes the operation and returns to its menu;
window close/Escape while busy also minimizes. Only the explicit Cancel operation
button requests cancellation. Minimizing does not cancel copying.

Read-only Node/Core configuration exports and previews use shared configuration
locks independently of the Core lifecycle lock. Thus a blockchain backup can
copy while either/both configuration exports run. Core start/restart, wallet
operations, configuration changes and another chain operation remain serialized.
A blocked operation gives a useful conflict message, not a silent click.
Watch-only export/restore still needs a running Core and cannot run while the
chain backup has deliberately stopped it. The feature does not secretly restart
Core or directly copy a live wallet database to get around that constraint.

## Chain backup

The confirmation reads: “I understand that Core will stop while the backup is
created.” A completed, failed or cancelled backup never restarts Core. The user
starts it manually when ready. Import retains its existing restart behavior.
The existing byte checks, complete-copy publication and rollback are retained.

## Optional encryption

Watch-only, Bitcoin Core configuration and Node configuration exports all have
an explicit **Encrypt backup (optional)** checkbox, off by default. Plain exports
are `.json` envelopes with an embedded content checksum; encrypted exports remain
GPG AES256-MDC with actual decrypt verification. Existing `.gpg` backups remain
readable. There is no minimum passphrase length or strength/composition rule:
`1` works when encryption is selected and confirmed. An encrypted file needs a
nonempty passphrase; bounded transport and GPG text-input limits still apply.
No error causes automatic downgrade from encryption to plaintext.

The plain-file warning is shown before saving. A plain Node configuration may
contain Wi-Fi passwords and WireGuard private keys. A checksum detects damage,
not malicious replacement or source authenticity. Restore still requires preview,
explicit trust confirmation, strict schema validation and matching version/network.
The UI reports a missing path or mismatched confirmation instead of silently
ignoring a disabled action. Strong passphrases remain recommended, not mandated.

## PSBT Transfer Folder

Files → Places shows **Core**, **Private Workspace**, **PSBT Transfer Folder**,
then other user bookmarks. Files still opens the Core view initially. On Home,
when Watch-Only Wallets becomes visible, PSBT Transfer Folder appears immediately
next to it, before Private Workspace. The final Node Guide stays centered.

The active transfer directory is `/run/core-node-private/psbt`, under the existing
verified `noswap,nodev,nosuid,noexec` tmpfs. The fixed desktop/Core accounts share
it, and both receive a home shortcut. There is no disk fallback. Saved PSBTs
are lost on shutdown/restart; either RAM folder being nonempty triggers the
existing save-warning/countdown flow. Copy required files to USB first.

The former persistent `/var/lib/bitcoin-core-node/transfer` is not erased or
migrated automatically. Its old files, if any, remain on disk. Existing user
files are never silently discarded to implement the new RAM policy.

## Visual changes

Settings follows Home's five-column layout with a centered partial final row
(nine tools = five plus four). Narrow windows fall back to three columns.
Icon optical scaling now respects the requested canvas size at every size,
removing the old hardcoded-38px crop in 28px icon slots. Full 42px settings icons
match the existing visual family. All four Backup and Restore categories have
icons. Core status uses a live local-RPC dashboard, validation progress, numeric
cards, privacy/storage summary and expandable details. The activity indicator
pulses only during reported initial validation with networking and peers.
Missing or stopped-node values are not shown as invented successful results.

Physical T550/USB testing remains required. Test reports distinguish modeless
X11 copy fixtures, real native Core/GPG tests, and exact ISO boot acceptance.
